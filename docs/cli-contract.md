# Контракт CLI

Это решение дёшево принять сейчас и дорого менять потом: на CLI держится
клиентская панель, а её видят конечные пользователи.

## Правило

`xkop` отдаёт **тот же набор команд с теми же полями JSON**, что и podkop,
за исключением всего, что называется по движку. Тогда панель работает
с обоими проектами без правок, и переезд роутера с podkop на xkop не требует
трогать панель.

## Что вызывает панель клиента

Проверено по её исходникам:

```
xkop check_dns_available
xkop check_fakeip
xkop check_sing_box        -> переименовать в check_engine
xkop get_subscription_userinfo
xkop subscription_update
```

## Что дополнительно вызывает LuCI

```
check_logs            check_nft_rules       get_status
get_system_info       global_check          show_config
start / stop / restart / enable / disable
subscription_update   get_subscription_userinfo
dns_failover_retry_original
```

## Переименования по движку

| podkop | xkop | причина |
|---|---|---|
| `check_sing_box` | `check_engine` | движок сменился, имя не должно его называть |
| `get_sing_box_status` | `get_engine_status` | то же |
| `show_sing_box_config` | `show_engine_config` | то же |
| `clash_api` | `stats` | у Xray нет Clash API |

Поля внутри JSON тоже переименовываются: `sing_box_installed` становится
`engine_installed` и так далее.

**Совместимость обеспечивается алиасами.** `xkop check_sing_box` работает
и отдаёт то же, что `check_engine`, чтобы старая панель не сломалась.
Алиасы помечаются устаревшими и живут до тех пор, пока панель не обновится.

## Команды, добавленные сверх podkop

| Команда | Зачем |
|---|---|
| `dashboard` | всё, что показывает обзор, одним запуском |
| `service <start\|stop\|restart\|enable\|disable\|status>` | действие и следом состояние, которое из него получилось |
| `keep` | удержание выбранного узла, ставится в расписание |
| `nodes`, `select` | пул и закрепление узла |
| `explain`, `recent` | разбор маршрута по журналу доступа |
| `canary` | обнаружение подмены DNS |
| `update`, `check_update` | обновление пакетами |

`dashboard` появился не для красоты: обзор вызывал пять команд на отрисовку,
две из них ждали сеть, и браузер обрывал запрос раньше ответа. Одна команда
считает всё дорогое ровно один раз.

`service` не заменяет `start`/`stop`/`restart` — они остаются. Разница в том,
что `service` возвращает состояние, которое получилось: «команда отработала»
и «движок поднялся» — разные утверждения, и различать их должен не интерфейс.

## Чего нет и почему

`dns_failover_retry_original` — возвращения к исходному резолверу после
автопереключения. Самого автопереключения в xkop нет: его заменяет разбор
в `dns.md` — параллельный опрос нескольких резолверов и отбраковка ответа
по `unexpectedIPs`. Переключаться по таймауту незачем, когда ложный ответ
отбраковывается в момент получения, а живой резолвер отвечает параллельно.

Если автопереключение всё же понадобится, команда возвращается вместе с ним,
а не раньше.

## Правила, которые нельзя нарушать

**Всё выводится в JSON.** Панель и LuCI разбирают вывод, а не читают его.
Человекочитаемое идёт в лог, не в stdout.

**Пустой вывод недопустим.** Команда, которой нечего сказать, отдаёт
структуру с признаком «не удалось», а не пустоту. На этом уже обжигались:
пустой вывод `check_fakeip` был неотличим от честного отрицательного ответа,
и диагностика показывала поломку там, где просто не было связи.

**Причина отказа отдаётся отдельным полем.** Не «не удалось», а что именно
не удалось: недоступен сервис, нет места, отвергнута подписка. Интерфейс
не должен додумывать причину — он уже додумывал, и врал.

**Код возврата не заменяет содержимое.** Ноль означает «команда отработала»,
а не «всё хорошо». Состояние передаётся полями.

## Источник данных для дашборда

Решено: метрики Xray по `http://127.0.0.1:11111/debug/vars`. Оттуда берётся
и трафик по каждому исходящему, и задержки узлов.

Команда `stats` отдаёт это в том же виде, что остальные команды CLI, — панель
не должна знать ни про формат Xray, ни про адрес эндпоинта.

Переключение активного сервера идёт через балансировщик, а не через прямую
подмену исходящего.

Команда реализована, её конверт, коды отказа и единицы измерения описаны
в `stats.md`.
