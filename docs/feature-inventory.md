# Инвентарь возможностей

Правило: **xkop не имеет права быть беднее podkop**. Новое — приветствуется,
потеря существующего — нет. Этот список нужен, чтобы ничто не осиротело
незаметно.

Собран из кода podkop, а не по памяти: 25 общих настроек и 34 настройки
секции.

## DNS — самый нагруженный узел

Здесь больше всего накопленного, и здесь же самая частая боль.

**Транспорт и сервер**
- `dns_type`: udp, doh, dot
- `dns_server`: адрес или имя, для DoH с путём (`8.8.8.8/dns-query`)
- `bootstrap_dns_server`: резолв имени DoH-сервера
- `dns_rewrite_ttl`

**Локальный резолвер как апстрим.** Рабочий сценарий: `dns_server` указывает
на AdGuard Home или Pi-hole в локальной сети, и весь фильтрующий слой
пользователя остаётся на месте. Это не крайний случай, а первоклассный режим:
у части пользователей вся фильтрация рекламы держится на нём.

Следствия, которые уже выявлены на podkop:
- проверка доступности для локального адреса не должна приводить к
  переключению при обычной недоступности — перезапуск AGH не повод менять DNS;
- но перехват провайдером апстрима AGH обязан быть виден: локальный сервер жив
  и отвечает, а раздаёт подменённые адреса;
- переключение в обход локального резолвера — отдельная осознанная опция
  (`dns_failover_on_local`), потому что ценой будет потеря фильтрации.

**Отказоустойчивость**
- автопереключение при недоступности, список запасных
- детект перехвата порта 53 запросом к адресу, где резолвера быть не может
- при подтверждённом перехвате — только шифрованные транспорты, заданные
  IP-литералами, чтобы не зависеть от bootstrap-резолва
- возврат к исходному DNS по команде

**Защита от обхода клиентами**
- отклонение записей HTTPS (ломает автообнаружение DoH браузерами)
- отклонение канарейки Firefox
- блокировка известных публичных DoH на 443 и всего порта 853 (DoT и DoQ)
- отклонение PTR

**Прочее**
- FakeIP и перехват DNS клиентов на инбаунд движка
- `dont_touch_dhcp` — не трогать dnsmasq, если пользователь настроил сам
- `domain_resolver_*` на уровне секции — свой резолвер для секции

## Маршрутизация

- списки сообщества (`community_lists`) — база, от которой отказываться глупо
- удалённые списки доменов и подсетей
- локальные списки доменов и подсетей
- пользовательские домены и подсети, статические и динамические
- `fully_routed_ips` — источники, чей трафик идёт целиком в туннель
- `routing_excluded_ips` — источники, исключённые из маршрутизации
- `source_network_interfaces` — с каких интерфейсов берём трафик
- `output_network_interface` — через какой выпускаем
- `disable_quic`
- `exclude_ntp`

## Соединения

- типы: proxy, vpn, block
- источники: подписка, ссылка, готовый JSON исходящего, список ссылок
- протоколы: vless, shadowsocks, trojan, socks, vmess, hysteria2, wireguard
- `enable_udp_over_tcp`
- смешанный прокси на отдельном порту (`mixed_proxy_*`)

## Подписки

- три формата: base64-список, конфиги Xray, JSON движка
- выбор User-Agent — от него зависит и формат, и состав серверов
- интервал обновления, распаковка gzip
- кэш, переживающий перезагрузку и отсутствие сети
- отказ от применения непригодного ответа, память об отвергнутом
- заголовок с трафиком и сроком подписки
- фильтр серверов по ключевым словам, включающий и исключающий
- группировка по странам

## Выбор сервера

- автоматический по задержке, интервал и допуск
- ручной выбор
- своя ссылка для замера

## Служебное

- мониторинг WAN и перезагрузка при подъёме интерфейса
- обновление списков по расписанию
- загрузка списков через прокси
- уровень логирования
- веб-интерфейс статистики с доступом из WAN и ключом
- диагностика: DNS, движок, правила nft, FakeIP, исходящие
- просмотр логов и конфигурации

## Что добавляется сверх

- распределение трафика числом: напрямую, через туннель, заблокировано
- слияние подписок, забранных разными User-Agent
- несколько подписок в один пул
- карантин мёртвых серверов вместо выбрасывания
- разброс расписания обновления между роутерами
